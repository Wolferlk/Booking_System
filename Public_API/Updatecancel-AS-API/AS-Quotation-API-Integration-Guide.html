1. Purpose and architecture

This API allows AppleSystem (AS) to drive the OPS booking lifecycle. When a quotation is confirmed, AS creates an OPS booking. When the quotation changes, AS sends an amendment. When the quotation is cancelled, OPS is automatically moved to CANCELLED and any applicable cancellation fee is recorded.

SystemResponsibility
AppleSystemCreates, revises, and cancels quotations; supplies quotation numbers, reference IDs, itinerary data, and commercial decisions.
OPS Public APIAuthenticates AS, resolves the matching booking, imports or updates the booking, records audit information, and returns a standard JSON response.
OPS booking systemStores operational booking data, status history, versions, cancellation details, and notification results.

The integration does not introduce new database tables or columns. It writes to existing booking, booking-version, status-event, and activity-log structures.

Lifecycle flow

AppleSystem                         OPS Public API                 OPS booking
    |                                      |                            |
    | POST /auth/login                     |                            |
    |------------------------------------->|                            |
    |              bearer token            |                            |
    |<-------------------------------------|                            |

    |------------------------------------->| version + amendment trail  |
    |                                      |--------------------------->|
    | POST /quotation/cancel               |                            |
    |------------------------------------->| status → CANCELLED         |
    |                                      |--------------------------->|

3. Authentication

3.1 Login — POST /auth/login

Exchange the AS integration username and password for a bearer token. The token is valid for 12 hours by default (configurable on the server).

curl -X POST 'https://ops.aahaas.com/api/public/as/v1/auth/login' \
  -H 'Content-Type: application/json' \
  -d '{"username":"as_integration","password":"<stored-secret>"}'
{
  "success": true,
  "message": "Authenticated",
  "data": {
    "access_token": "<JWT>",
    "token_type": "Bearer",
    "expires_in": 43200,
    "expires_at": "2026-08-01T20:00:19.122Z",
    "scopes": ["*"]
  },
  "request_id": "<uuid>",
  "timestamp": "2026-08-01T08:00:19.129Z"
}

Cache the token. Re-authenticate approximately one minute before expiry, or after one 401 UNAUTHORIZED. Do not log in for every request.

3.2 Verify token — GET /auth/verify

curl 'https://ops.aahaas.com/api/public/as/v1/auth/verify' \
  -H 'Authorization: Bearer <access_token>'

Use this low-cost probe before a batch operation. A valid response includes data.valid: true, the client name, and scopes.

3.3 Authentication failures

StatusCodeMeaning / action
401INVALID_CREDENTIALSCredentials are wrong. Stop and alert; do not repeatedly retry.
401UNAUTHORIZEDToken missing, invalid, or expired. Login again once.
422CREDENTIALS_REQUIREDUsername or password was not supplied.
429TOO_MANY_ATTEMPTSEight failed logins trigger a five-minute lockout. Back off.
503NOT_CONFIGUREDOPS has no configured API client. Contact the OPS administrator.

Alternative: a static x-api-key may be configured, but bearer authentication is preferred. Treat an API key like a password.

4. Booking identifiers and common conventions

Most write requests require one booking identifier. Resolution accepts these names and aliases:

FieldExamplePurpose
is_numberIS48748OPS IS number / booking reference. Case and surrounding spaces are normalized.
booking_refIS48748Alias for the IS number.
quotation_no479416CNTLAppleSystem quotation reference; the most recent matching booking is used.
reference_id18452AppleSystem list-row ID. Required when OPS must pull the quotation template.

Accepted spelling aliases include isNumber, quotationNo, referenceId, ref_number, and quotation_ref.

5. Quotation lifecycle endpoints

5.1 Create booking — POST /quotation/create

Imports the quotation from AppleSystem and creates an OPS booking in DRAFT. The import includes dates, passengers, hotels, itinerary, contacts, pricing, and mapped quotation information.

{
  "quotation_no": "479416CNTL",
  "reference_id": "18452",
  "is_number": "IS48748"
}

quotation_no and reference_id are required. is_number is optional when the template contains the IS number.

Idempotency: first success normally returns 201. A repeated request returns 200 with already_exists: true and does not create a duplicate. This makes timeout retries safe.

5.2 Update booking — POST /quotation/update

The endpoint also accepts PUT and PATCH. Use the re-pull path when AppleSystem has a revised quotation:

{
  "is_number": "IS48748",
  "quotation_no": "479416CNTL",
  "reference_id": "18452",
  "amendment_note": "Revision 3 - hotel changed in Kandy",
  "force_replace_details": false,
  "create_if_missing": false
}

Header fields are refreshed. Passenger, hotel, and itinerary child records are replaced only for early statuses such as DRAFT, BT_CONFIRMED, GT_REVIEW, CHANGE_REQUESTED, and GT_VERIFIED. Set force_replace_details: true only when an approved operational decision permits overwriting advanced booking details.

The response contains an incremented version, changed_fields, and details_replaced. The API also records a version snapshot and status event.

5.3 Patch fields only

When no reference_id is supplied, no AppleSystem round-trip occurs. Only explicit fields are applied:

{
  "quotation_no": "479416CNTL",
  "amendment_note": "Pax corrected by agent",
  "fields": {
    "pax_adults": 3,
    "pax_children": 1,
    "quoted_total": 690.00,
    "currency": "USD",
    "arrival_date": "2026-08-08",
    "departure_date": "2026-08-14"
  }
}

Allowed keys: arrival_date, departure_date, pax_adults, pax_children, pax_infants, quoted_total, currency, agent, file_handler, contact_email, contact_phone, package_includes, package_excludes, important_notes, and quotation_no.

create_if_missing: true can import a missing booking, but requires both quotation_no and reference_id. Cancelled and completed bookings cannot be updated.

5.4 Cancel booking — POST /quotation/cancel

The endpoint also accepts DELETE. It immediately changes the booking to CANCELLED; it does not wait for an accounts approval step.

{
  "is_number": "IS48748",
  "reason": "Guest cancelled the trip",
  "cancellation_fee": 150.00,
  "currency": "USD",
  "cancelled_by": "Nimal Perera",
  "cancelled_by_email": "nimal@appleholidays.lk",
  "suppress_email": false
}

For multiple charges, send itemized fees instead of cancellation_fee. The server recomputes the total:

{
  "is_number": "IS48748",
  "reason": "Guest cancelled",
  "cancellation_fees": [
    {"note":"Hotel one-night penalty", "amount":120},
    {"note":"Non-refundable entrance tickets", "amount":30}
  ]
}

On cancellation, OPS stores the previous status, cancellation timestamp, reason, caller details, fee lines, total fee, automatic approval trail, and a status event. It sends the standard cancellation notice unless suppress_email: true. A mail failure does not roll back the cancellation; the response reports email_sent: false.

Repeated cancellation is safe: an already-cancelled booking returns 200 with already_cancelled: true. Completed or otherwise non-cancellable bookings return 409 NOT_CANCELLABLE.

5.5 Read status — GET /quotation/status

This is read-only and should be used before or after a lifecycle operation:

GET /quotation/status?is_number=IS48748
GET /quotation/status?quotation_no=479416CNTL

The response includes whether the booking was found, cancellation state, booking status, version, dates, passenger totals, pricing, and update timestamp.

7. Response envelope and error handling

Every response includes a consistent envelope. Save the request_id and quote it when reporting a problem.

// Success
{"success":true,"message":"...","data":{...},"request_id":"<uuid>","timestamp":"<ISO-8601>"}

// Failure
{"success":false,"error":"...","code":"MACHINE_CODE","request_id":"<uuid>","timestamp":"<ISO-8601>"}
StatusCodesRecommended handling
400INVALID_JSON, INVALID_BODYFix JSON/object shape.
401UNAUTHORIZED, INVALID_CREDENTIALSRe-login once for an expired token; stop for bad credentials.
403UNAUTHORIZED scopeStop and request the required scope.
404BOOKING_NOT_FOUNDFor create flows, create/import; for cancellation, normally ignore if never imported.
409BOOKING_CANCELLED, BOOKING_COMPLETED, NOT_CANCELLABLE, IDENTIFIER_MISMATCH, COUNTRY_MISMATCHDo not blindly retry. Resolve the business conflict.
422IDENTIFIER_REQUIRED, INVALID_FIELD, INVALID_FEE, NOTHING_TO_UPDATE, QUOTATION_NOT_MAPPABLE, COUNTRY_UNRESOLVEDCorrect the request or source quotation.
429TOO_MANY_ATTEMPTSBack off for the lockout period.
500/502/503INTERNAL_ERROR, UPSTREAM_UNAVAILABLE, NOT_CONFIGUREDRetry transient failures with backoff; alert for configuration failures.
Retry policy: retry 500, 502, and 503 with exponential backoff. Create and cancel are designed to be safe to retry. Retry 401 once after re-login. Do not retry normal 4xx validation or business errors.

8. Integration implementation pattern

  1. Store the API username and password in a secret manager or protected environment configuration.
  2. Login once and cache the token until one minute before expiry.
  3. Send the bearer token and JSON headers on every API call.
  4. Persist the API response and request_id in the AS integration log.
  5. For transient failures, enqueue a retry with exponential backoff.
  6. For a 401, refresh the token once and retry the original operation.
  7. For business errors, stop retrying and notify the responsible operator.

Recommended event mapping

AppleSystem eventAPI callNotes
Quotation confirmed / IS issuedPOST /quotation/createSafe to retry; idempotent.
Quotation revisedPOST /quotation/update with reference_idRe-pulls the latest template.
Small correctionPOST /quotation/update with fieldsNo AppleSystem round-trip.
Quotation cancelledPOST /quotation/cancelInclude fee data when applicable.
Unified webhookPOST /quotation/syncSet action to CREATE, UPDATE, or CANCEL.

Minimal PHP client pattern

$base = 'https://ops.aahaas.com/api/public/as/v1';

// Login once; cache data.access_token and data.expires_in.
$login = postJson($base . '/auth/login', [
  'username' => getenv('OPS_API_USERNAME'),
  'password' => getenv('OPS_API_PASSWORD'),
]);
$token = $login['data']['access_token'];

// Create after quotation confirmation.
$result = postJson($base . '/quotation/create', [
  'quotation_no' => $quotationNo,
  'reference_id' => $referenceId,
  'is_number' => $isNumber,
], $token);

// Cancel from the AS cancellation hook.
$result = postJson($base . '/quotation/cancel', [
  'is_number' => $isNumber,
  'reason' => $reason,
  'cancellation_fee' => $fee,
], $token);

The client should treat a response with HTTP status 400 or higher, or success: false, as an error and include the returned machine code and request ID in logs.

9. Postman setup and safe testing

  1. Import AS-Quotation-API.postman_collection.json.
  2. Import AS-Quotation-API.postman_environment.json.
  3. Select the environment targeting https://ops.aahaas.com.
  4. Set as_username and as_password from the approved secret store; do not commit real credentials.
  5. Run Auth → Login; its test script stores access_token.
  6. Run Auth → Verify token.
  7. Run only Status requests for read-only validation unless a test booking has been approved.
Safe live probes: GET /auth/verify with a valid token and GET /quotation/status?is_number=IS00000 using a deliberately nonexistent identifier. These do not create, update, or cancel a booking.
Do not use these against live without approval: Create booking, both update requests, all cancel requests, and all sync requests with CREATE, UPDATE, or CANCEL actions. They change OPS data and may send cancellation email.

For a full rehearsal, use a non-production OPS database and a dedicated test quotation. Validate the sequence: create → status → update → status → cancel with fee → status confirms CANCELLED.

10. Security and production configuration

OPS server configuration should include:

AS_PUBLIC_API_USERNAME=as_integration
AS_PUBLIC_API_PASSWORD=<long-random-secret>
AS_PUBLIC_API_CLIENT_NAME=AppleSystem Integration
AS_PUBLIC_API_JWT_SECRET=<fresh-random-signing-key>
AS_PUBLIC_API_TOKEN_TTL_MIN=720
  • Use HTTPS in production.
  • Keep credentials out of source control, Postman exports, application logs, and error messages.
  • Use a fresh JWT secret; do not rely on a development fallback.
  • Prefer restricted scopes for read-only clients: quotation:read.
  • Review the cancellation notification list before enabling automatic cancellation.
  • Monitor ActivityLog, StatusEvent, request IDs, and failed retries.
  • Never use the sample development password in production.
